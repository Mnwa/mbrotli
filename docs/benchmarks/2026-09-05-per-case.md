# Per-case throughput optimization

**The 95% target is not met.** The latest per-case assessment passes **244 of
658** individual Rust/C comparisons; **414** fall below 95% of C throughput.
It combines a complete 658-pair sweep (241 passes) with a 64-pair follow-up of
the final fast-output adjustment. The other 594 results come from the full sweep.
No quality-wide average is used to satisfy the target.

The [case CSV](2026-09-05-per-case.csv) records every comparison, compressed sizes,
confidence bounds, and pass/fail. Its `timing_run` column identifies each result's
source. The 64 follow-up rows also record the directly preceding Rust/C times.

The cold sweep improved from 15/132 passing cases in the starting measurement to
45/132. That improvement does not establish compliance for the other API shapes.
The earlier [greedy SIMD report](2026-09-05-intel-i7-13700kf.md) describes the first,
smaller optimization step and its original-HEAD comparison.

## Measured changes

All times below are mean microseconds. The starting executable already contains
the first greedy feature-context optimization; the earlier report provides its
comparison with repository HEAD. The CSV retains these starting times for all
132 cold cases, including slowdowns.

| Cold case | Rust start | Rust after | C after | Rust speedup | Compressed bytes, both |
| --- | ---: | ---: | ---: | ---: | ---: |
| q0 text 1 MiB | 369.61 | 101.68 | 94.89 | 3.64× | 27,963 |
| q1 text 1 MiB | 508.82 | 171.69 | 175.91 | 2.96× | 10,001 |
| q2 text 1 KiB | 6.62 | 3.94 | 2.40 | 1.68× | 174 |
| q5 compressible 256 KiB | 335.90 | 40.13 | 103.62 | 8.37× | 19 |
| q9 compressible 256 KiB | 228.77 | 44.24 | 48.48 | 5.17× | 19 |
| q11 Alice | 143,938.42 | 139,309.81 | 133,163.44 | 1.03× | 46,487 |

Some cases regress. In the complete sweep before the final outlined-growth
adjustment, q1 structured binary and maps were approximately 8% slower than the
starting run, and several q1 text cases were 4–6% slower. C control
times also vary between runs. The CSV exposes absolute times and uncertainty;
passing-count changes must not all be attributed to source changes.

The final adjustment moves vector growth/initialization into a cold helper.
The AVX2 q0 vector-output body shrinks from 20,827 to 14,277 bytes; its fixed-slice
counterpart retains the same size. In a separate paired 64-case comparison,
q0 tiny cases improve 1.5–5.0%, and q1 cold Alice/lcet10 improve about 4%.
Some q1 tiny cases slow by up to 3.8%. The median Rust speedup over those 64 cases
is only 1.004×; this is a modest, mixed result, not a broad throughput gain.
Passing cases in that directly paired follow-up increase from 30 to 32.
Median C time drift is +0.81%, with larger changes in some controls; for example,
the q0 text-1MiB threshold flips despite essentially unchanged Rust time.
The helper is retained for its smaller code and measured q0 tiny-input gains.

The implementation changes address measured work:

- Greedy, fast, and HQ search bodies enter their selected `fearless_simd` feature
  context. AVX2 comparisons and masks inline into the search rather than making
  repeated calls to operation helpers. Scalar behavior and candidate order remain
  independently tested.
- The ring buffer grows its written prefix until a wrap requires the full layout.
  Deferred tail copies preserve the original sentinel and short-first-write rule.
- Continuation copy extension uses the selected SIMD match scanner, bounded at
  both physical wrap points, instead of comparing every byte separately.
- Shallow tagged buckets compute one 16/32-slot mask, retain newest-first order,
  and promote compact payloads to direct indexing once sufficiently occupied.
- Short q2–q4 inputs keep the original logical hash slots in a small growing map.
  Clean matcher state avoids a redundant sweep; entropy workspace initializes
  only the tables an emitted block needs.
- Fast vector output writes into initialized portions of the caller's vector,
  avoiding full scratch initialization and a second output copy. Fixed-slice and
  growing paths share the same algorithms through static specialization.
- Empty one-shot output emits the resolved header and terminal bits directly.
  Shared copy-length pricing uses an exact compile-time class table.

Separate release `hotpath-cpu` workloads identified ring initialization at 44%
then scalar copy extension at 51% of repeated-input runtime. On Alice, greedy
match search accounted for about 85%; on q11 Alice, Zopfli iteration accounted
for about 55%. These are inclusive function timings from different profiling
runs, not additive percentages. The optional CPU sampling worker was unavailable.
The earlier optimization also ran the allocation instrumentation separately.

The remaining deficits require further work on tiny-call construction, greedy
match search on binary/real corpora, HQ search/cost evaluation, and streaming
copy/delivery costs. The present measurements do not establish that one further
change can close every gap.

## Reproduction and scope

- CPU: Intel Core i7-13700KF, logical CPU 2; WSL2 Linux 6.18.33.2.
- Rust 1.98.1, LLVM 22.1.8, `x86_64-unknown-linux-gnu`; GCC 11.4.0.
- Reference: Google Brotli `028fb5a23661f123017c060daa546b55cf4bde29`.
- Base repository revision: `b8c41a16752036bbcbccc424fddf4ab851e44465`.
- Default-feature optimized builds, default target flags, runtime SIMD selection.
- The unchanged `compress` timing loops cover deterministic text, structured
  binary, compressible and incompressible generators plus all six vendor fixtures.
  Window 22 applies except the universal group, which uses window 10.
- C uses matching streaming FINISH/flush/dictionary settings. Reused and presized
  C cases recreate C encoder state while Rust retains its workspace. Streaming C
  normalization includes its staging costs. Dictionary-free controls use different
  settings and are excluded from the 658 pairs.
- Timings ran without concurrent Rust compilation, Rust tests, coverage, or AFL.
  Criterion has ten samples, 100 ms warm-up and 200 ms target measurement, except
  qualities 10/11 use the harness's 1 s/3 s policy. The focused follow-up uses 300 ms warm-up and
  600 ms target measurement. Slow cases extend measurement.
- The harness validates ordinary, streaming, flush, dictionary and universal
  output against C. A separate executable using the harness's `validate` function
  checked all 48 tiny quality/size payloads and recorded their sizes. These tiny
  checks were performed after timing. The current harness now also validates tiny
inputs before timing. All recorded compressed sizes agree.

python3 scripts/compare_benchmarks.py --baseline per-case-final --expected-cases 658 --csv /tmp/mbrotli-per-case-final.csv
