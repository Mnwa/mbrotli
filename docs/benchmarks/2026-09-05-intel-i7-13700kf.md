# Greedy SIMD feature-context comparison

Moving each specialized greedy search body into `S::vectorize` improves the
geometric mean of cold throughput by **7.4% at q5, 4.6% at q7, and 17.4% at q9**
over eleven corpora per quality. All 132 quality/corpus output checks remain
byte-identical to C. These are measurements on one x86-64 host, not a claim
about other processors.

The [CSV](2026-09-05-intel-i7-13700kf.csv) records all 98 timed cases, including
C controls, input and compressed sizes, mean times, and 95% confidence intervals.
Speedup is baseline Rust time divided by optimized Rust time.

## Selected cold results

Times below are arithmetic means in milliseconds. C uses matching streaming
FINISH settings, including the declared size, quality, and window.

| Quality | Corpus | Rust before | Rust after | C after | Rust speedup | Compressed bytes, both |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 5 | text-1MiB | 5.082 | 3.968 | 2.677 | 1.28× | 8,254 |
| 5 | alice29.txt | 4.307 | 4.085 | 2.308 | 1.05× | 52,809 |
| 6 | text-1MiB | 8.285 | 4.807 | 4.371 | 1.72× | 8,254 |
| 7 | text-1MiB | 5.246 | 3.846 | 4.298 | 1.36× | 7,586 |
| 7 | alice29.txt | 4.909 | 4.859 | 4.745 | 1.01× | 51,451 |
| 9 | text-1MiB | 5.459 | 3.814 | 9.779 | 1.43× | 7,542 |
| 9 | alice29.txt | 6.239 | 6.274 | 11.062 | 0.99× | 51,054 |
| 9 | quickfox_repeated | 0.0925 | 0.0324 | 0.0629 | 2.86× | 51 |

Rust still trails C on the q5 cases above; q9 wins these cold comparisons with C.
The largest gain is on long repeated matches. Tiny inputs and real-text q7–q9
inputs generally change much less.

There are small regressions: q7 binary-256KiB takes 1.4% longer, q7 plrabn12.txt
1.9% longer, and q9 binary-256KiB 2.3% longer. Their time-change confidence
intervals exclude zero. Other small decreases in the CSV have intervals spanning
zero. The change is retained for the measured aggregate gains without altering
compression decisions, workspace allocations, or the public API.

The q5 reused Alice case improves 7.1%; its reader, writer, and session cases
improve 6.7–7.7%. The corresponding q9 cases are essentially unchanged. The
reused C arm creates encoder state for each operation, as the existing harness
documents; it does not imply that C retains the Rust workspace between streams.

Qualities 2, 3, 4, 6, and 8 were additionally sampled on text-1MiB and Alice.
Those two-case samples are not directly comparable to the eleven-case geometric
means above. Qualities 0–1 and 10–11 were validated but not timed in this sweep.

## Why it helps

The release `hotpath-cpu` example, with Alice as its optional corpus, attributed
56.8% of its measured time to greedy reference generation and only 0.11% to
bucket-matcher construction. These are inclusive function timings; the optional
CPU sampling worker was unavailable. An allocation-mode run also completed;
the final optimization changes no allocation policy.

The original out-of-line generic search function received the correct SIMD
token, but its compilation context still used baseline target features. The
AVX2 H5-wide search had 18 static calls to SIMD operation helpers and no native
vector comparison or mask instructions in its own body.

The specialized search closure now enters the selected feature context after
matcher selection. The corresponding AVX2 body contains six native vector byte
comparisons and six mask extractions, with zero SIMD-helper call sites. It is
12,386 bytes versus 12,900 bytes for the original body. Feature detection and
virtual dispatch stay outside the loop, and each matcher keeps a separate body.
The scalar implementation, search order, and exact match-length results remain
the same. See the [greedy specification](../../architecture/greedy-encoder.md).

The older Apple M5 Pro reports describe a different revision, platform, and
benchmark grouping. They suggested investigating greedy qualities but are not
the baseline for the speedups recorded here.

## Reproduction

- Baseline: `b8c41a16752036bbcbccc424fddf4ab851e44465`.
- CPU: Intel Core i7-13700KF; Linux 6.18.33.2-microsoft-standard-WSL2.
- Rust: 1.98.1, LLVM 22.1.8; target `x86_64-unknown-linux-gnu`.
- C compiler: GCC 11.4.0; pinned C Brotli `028fb5a23661f123017c060daa546b55cf4bde29`.
- Default-feature release benchmark builds, default target flags, runtime SIMD
  selection, window 22. No whole-binary `target-cpu=native` setting.
- Identical deterministic generators and six vendor fixtures from
  `benches/compress.rs`; setup and validation follow that harness's API modes.
- Both binaries pinned to logical CPU 2; 20 samples, 300 ms warm-up, 1 s target
  measurement time, 10,000 bootstrap resamples. Criterion lengthens slow cases.
- Final before/after timing passes ran without concurrent builds, tests, coverage,
  or fuzzing. Earlier exploratory runs were excluded. Median C-control time
  drift across the final sweep was +0.12%.

Build `cargo bench --bench compress --locked --no-run` on the baseline and the
changed source, preserving the resulting executables separately. The recorded
commands were:

```sh
bench_filter='(cold/q(5|7|9)/|cold/q(2|3|4|6|8)/.*/(text-1MiB|vendor-alice29.txt)$|(reused|streaming)/q(5|9)/.*/vendor-alice29.txt$)'
taskset -c 2 /tmp/mbrotli-before-bench --bench "$bench_filter" --warm-up-time 0.3 --measurement-time 1 --sample-size 20 --nresamples 10000 --save-baseline final-before
taskset -c 2 /tmp/mbrotli-vectorize-bench --bench "$bench_filter" --warm-up-time 0.3 --measurement-time 1 --sample-size 20 --nresamples 10000 --baseline final-before
```
