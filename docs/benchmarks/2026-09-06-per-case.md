## What changed

- The bucket matcher (q5–q9) picks one of three storage layouts per stream:
  a compact key map for one-shot inputs of at most 1 KiB, generation-stamped
  sparse entries with on-demand blocks otherwise, and the reference's dense
  key-addressed table only when the matcher was built for a size hint above
  the shape's dense limit. Preparation is self-cleaning, so a warmed encoder
  allocates nothing and never replays a sweep.
- Tag filtering computes one comparison mask per bucket and splits it at the
  newest slot, walking newest to oldest as two ascending scans. The quick
  matchers' small-slot map is sized for the input at preparation.
- The greedy loop keeps its state in locals passed by value through the commit
  path, forwards through a per-block `MatchRun` view that borrows the tables
  once (the equivalent of C's `restrict`), and uses `u32`-masked offsets so
  each bounded read compiles to a single compare.
- Prefix-length scans share one word-at-a-time scanner; the attached-dictionary
  prefix search uses its SIMD variant inside the selected feature context.
- The block splitter sums histogram entropies in place instead of materializing
  combined histograms; the dictionary probe runs out of line behind an inline
  worth-probing check.

Callgrind (built from source; no PMU is exposed on this WSL2 host) showed the
q6 search loop executing about 30 instructions per candidate against C's 24,
with comparable cache misses and mispredictions. The remainder is bounds
checks that a safe formulation cannot drop, and register spills. Outlining the
search, a dense-by-key layout alone, and fat LTO with one codegen unit did not
help and were reverted.
